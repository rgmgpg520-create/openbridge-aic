## 第 0 步：把最终成果提交到本地 Git

在**所有修复和报告都完成后**执行一次。打开 PowerShell：

```powershell
cd D:\OpenBridge_AIC
git add -A
git status          # 核对将要提交的文件，确认没有 .mp4、权重、.venv、node_modules
git commit -m "feat: 提示词事实约束与检索修复、12题复核、盲评与离线演示、开放成果材料"
```

把本地分支统一改名为 `main`（与主流平台一致）：

```powershell
git branch -M main
```

## 第 1 步：注册并登录 Gitee（已有账号可跳过）

1. 浏览器打开 https://gitee.com ，用手机号注册并登录。
2. Gitee 的**公开仓库需要完成实名认证**（个人开发者，上传身份证，一般几分钟到几小时通过）。未认证时仓库可能只能私有，所以请先完成认证。

## 第 2 步：在 Gitee 新建一个**空**仓库

1. 登录后，右上角 **「+」→「新建仓库」**。
2. 填写：
   - **仓库名称**：`openbridge-aic`
   - **仓库介绍**：`OpenBridge 开源桥——基于 Requests 固定快照的 RAG 新手协作者（AIC 参赛作品）`
   - 选择 **「开源」（公开）**
3. **关键：下面所有"初始化仓库"选项都不要勾选**——不要勾选"使用 Readme 初始化""设置 .gitignore""选择许可证"，保持仓库为空，否则首次推送会冲突。
4. 点击 **创建**。创建后页面会给你一个仓库地址，形如：
   `https://gitee.com/你的用户名/openbridge-aic.git`
   把它复制下来。

## 第 3 步：把本地仓库推送到 Gitee

在项目目录的 PowerShell 中执行（把下面地址换成你第 2 步复制的地址）：

```powershell
cd D:\OpenBridge_AIC
git remote add origin https://gitee.com/你的用户名/openbridge-aic.git
git push -u origin main
```

- 推送时会弹出登录窗口或要求输入 Gitee 用户名和**密码/私人令牌**。按提示登录即可（Gitee 现在常用"私人令牌"当密码，在 Gitee「设置→私人令牌」生成一个勾选 `projects` 权限的令牌）。
- 看到 `Branch 'main' set up to track ...` 和 100% 即成功。

## 第 4 步：验证仓库是公开的、内容正确

1. 浏览器**退出登录（或用无痕窗口）**打开 `https://gitee.com/你的用户名/openbridge-aic`，确认：不登录也能看到代码、README 正常渲染。
2. 抽查以下内容存在且可打开：
   - `README.md`、`LICENSE`、`server.mjs`、`lib/`、`scripts/`
- `results/`、`dist/OpenBridge-离线演示.html`
   - `docs/试用盲评说明.md`、`docs/上游Issue草稿.md`
3. 确认仓库里**没有**：模型权重目录（`model/weights/`）、`.venv/`、`node_modules/`、`*.mp4`、`.tmp/`。

---

## 第 5 步（可选，但建议）：镜像到 GitHub

1. 注册/登录 https://github.com ，右上角 **「+」→「New repository」**。
2. 仓库名 `openbridge-aic`，选 **Public**，**不要**勾选任何初始化选项，创建。
3. 回到 PowerShell，添加第二个远程并推送：

```powershell
git remote add github https://github.com/你的用户名/openbridge-aic.git
git push -u github main
```

> GitHub 国内访问可能不稳定，评委主要看 Gitee，GitHub 作为国际镜像加分。
