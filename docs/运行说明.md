# OpenBridge 安装、部署与使用说明

> 只想尽快跑起来：见 `使用说明\运行说明.md`（四个入口、路径不同怎么办、常见提示）。本文是完整版，覆盖安装、部署、评测与异常处理。

本说明中的所有命令都**不依赖固定盘符**：先进入项目文件夹，再执行相对路径命令即可。文中出现的 `D:\OpenBridge_AIC`、`D:\anaconda3\...`、`D:\qwen\...` 只是开发机上的示例位置，换成你自己的路径时不需要改任何文件。

## 1. 运行环境

- Windows 10/11、Node.js 18+、现代浏览器。
- 网页工作台只依赖 Node.js：没有显卡、没有 Python、没有模型权重也能打开（界面显示「规则降级」）。
- 真实模型演示另需 Python 3.11（3.10 亦可）、可用的 PyTorch/CUDA 环境，以及本机的 `Qwen3-VL-2B-Instruct` 权重。
- 本项目不分发模型权重。默认在 `<项目>\..\qwen\Qwen\Qwen3-VL-2B-Instruct` 找权重，可用环境变量 `OPENBRIDGE_MODEL_DIR` 指到任意目录；使用者应从 Qwen 官方模型仓库获取并核对当期许可。

## 2. 一键启动（推荐）

双击项目内 **`使用说明\`** 文件夹里的 **`启动.bat`**：

1. 脚本自动定位项目目录（不认盘符），检查 Node.js；
2. 自动寻找带 `torch` + `transformers` 的 Python 和 Qwen 权重目录；
3. 启动网页工作台和本地模型服务，等待就绪后自动打开 `http://127.0.0.1:4173`。

其它入口：

| 文件 | 用途 |
| --- | --- |
| `使用说明\启动.bat` | 完整启动（网页 + 模型） |
| `使用说明\启动-仅网页.bat` | 只启动网页（无 GPU / 未装 Python 时） |
| `使用说明\诊断.bat` | 只做环境自检，不启动服务 |
| `dist\OpenBridge-离线演示.html` | 静态回放，双击即可看，不联网、不装任何东西 |

没有模型时脚本会说明原因并降级，不会卡住。

## 3. 手动启动

### 3.1 先进入项目文件夹

PowerShell 窗口里：

```powershell
cd "换成你解压后的项目文件夹"     # 路径有空格时一定要加引号
```

小技巧：在资源管理器里打开项目文件夹，地址栏输入 `powershell` 回车，就已经在当前目录了。

### 3.2 安装模型依赖（已有可用环境可跳过）

已配置好 Conda/PyTorch 环境时，直接用该环境的 Python 安装剩余依赖：

```powershell
& "你的环境\python.exe" -m pip install -r model\requirements.txt
```

没有可用环境时，按照 `docs\模型安装与许可.md` 创建独立环境（`.venv` 已被 `.gitignore` 忽略，不随提交包分发）：

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128
.\.venv\Scripts\python.exe -m pip install -r model\requirements.txt
```

如需重新安装 PyTorch，请根据本机 NVIDIA 驱动选择对应版本；不要在已有可用环境中重复安装不同 CUDA 版本。

### 3.3 启动本地 Qwen 服务

在第一个 PowerShell 中运行（命令里的相对路径以项目文件夹为当前目录）：

```powershell
.\.venv\Scripts\python.exe model\serve.py
```

已有自己的环境时，把前面的 Python 换成自己的，例如：

```powershell
& "C:\Users\你\anaconda3\envs\torch\python.exe" model\serve.py
```

等待出现下面的提示：

```text
OpenBridge Qwen service at http://127.0.0.1:8080
```

保持这个窗口运行。可在另一个 PowerShell 检查模型服务：

```powershell
Invoke-RestMethod http://127.0.0.1:8080/v1/models
```

### 3.4 启动网页工作台

在第二个 PowerShell 中运行：

```powershell
node server.mjs
```

浏览器访问 `http://127.0.0.1:4173`。网页右上角显示「本地 Qwen 模型在线」后，输入问题并点击「发送」。回答应包含 Requests 文件来源和证据片段，右侧代理轨迹应显示模型生成状态。

可用下面的地址检查网页服务：

```powershell
Invoke-RestMethod http://127.0.0.1:4173/api/status
```

## 4. 换目录、换电脑、路径不一致

**不需要改文件。** 启动脚本都在 `使用说明\` 里，以「自己所在位置的上一级」为项目根目录（`启动.bat` 用 `%~dp0..`，`start-openbridge.ps1` 逐级向上查找 `server.mjs`），因此下面这些情况都能直接双击运行：

- 解压到桌面、下载目录、`E:\评审材料\开源桥 2026\`；
- 路径里带空格或中文；
- 放在 U 盘 / 移动硬盘 / OneDrive 同步目录。

自动探测顺序：

1. **Node.js**：PATH → `Program Files\nodejs` → `%LOCALAPPDATA%\Programs\nodejs` → scoop → `D:\node-v20.0.0-win-x64`。
2. **Python**：`OPENBRIDGE_PYTHON` → 项目内 `.venv` → 当前 conda 环境 → `D:\anaconda3`、`%USERPROFILE%\anaconda3` 等常见位置 → `py -3.11` → PATH 里的 `python`。只采用能成功 `import torch, transformers` 的那个。
3. **模型权重**：`OPENBRIDGE_MODEL_DIR` → `<项目>\model\Qwen3-VL-2B-Instruct` → 上级 `qwen\Qwen\Qwen3-VL-2B-Instruct` → `D:\` / `C:\` / 用户目录 → Hugging Face 本地缓存（需含 `config.json`）。

路径确实不同、自动探测找不到时，用环境变量指定后重新双击 `使用说明\启动.bat`：

| 变量 | 作用 |
| --- | --- |
| `OPENBRIDGE_PYTHON` | 指向带 torch 的 `python.exe` |
| `OPENBRIDGE_MODEL_DIR` | 指向 Qwen 权重目录 |
| `OPENBRIDGE_MODEL_URL` | 指向其它 OpenAI-compatible 推理服务 |
| `PORT` | 网页端口（默认 4173） |
| `MODEL_PORT` | 模型端口（默认 8080，改了会自动同步给网页） |

```powershell
$env:OPENBRIDGE_PYTHON = 'E:\envs\torch\python.exe'
$env:OPENBRIDGE_MODEL_DIR = 'E:\models\Qwen3-VL-2B-Instruct'
```

## 5. 功能演示

1. 「项目总览」：展示固定 Requests 提交、索引资料和 RAG 工作流。
2. 「证据浏览器」：查看 7 条资料的 149 个分块与真实行号，并输入任意问题复现命中的资料、BM25 分值和证据窗口；该页不调用模型。
3. 「协作工作台」：提问 `Requests 的 get 方法在哪里实现？`，展示源码证据。
4. 继续提问 `贡献代码前要做哪些准备？`，展示贡献指南和测试证据。
5. 提问 `日志里可以放访问令牌吗？`，展示敏感信息护栏。
6. 生成 Issue 草稿或测试清单，人工填写和复核后再考虑外发。
7. 「效果验证」：点击「运行全部测试」，查看 32 条资料检索用例（含多跳、中英混问、提示注入、无证据四类）、来源精确率/召回率、证据覆盖率、提示注入、无据不答和 8 条护栏用例。
8. 「许可与风险」：查看 Requests、Qwen、OpenBridge 等 6 条资源的使用清单与许可说明。
9. 左侧「导入项目 JSON」：导入符合 `docs\项目JSON格式.md` 的项目；后续问答和验证都会使用该 JSON。项目若未配置 `testCases`，验证页会提示未配置专属测试。

以上顺序即为 3–5 分钟现场演示的推荐流程；每个环节的异常处理见第 7 节。

## 6. 评测与核验

在模型服务和网页服务均启动后，在第三个 PowerShell 中运行（当前目录仍是项目文件夹）：

```powershell
node scripts\benchmark.mjs      # 12 题“仅模型 vs 项目 RAG”，需要模型在线
node scripts\eval-retrieval.mjs # 55 条留出问题的纯检索评测，不需要模型
# 换一套题（20 条独立验证集）：$env:OPENBRIDGE_QUESTIONS='holdout-questions-v2.json'; node scripts\eval-retrieval.mjs
```

结果分别写入 `results/latest-results.json` 和 `results/holdout-results.json`。对照记录会区分模型生成与规则兜底，并保存每道题的逐句核验状态：`groundedClaims`（有据）、`paraphrasedClaims`（语义改写）、`unsupportedClaims`（含具体事实却无证据）。提交前需要人工检查答案、引用和模型状态。

如果只想确认服务可用，可运行 `node scripts\smoke-test.mjs`。

## 7. 停止服务与常见状态

- 在对应 PowerShell 按 `Ctrl+C` 停止服务；双击启动的，直接关闭弹出的 Node / Python 窗口。
- 显示「规则降级：模型未启动」表示网页仍可查看，但不能作为真实模型演示或模型准确率结果。
- 显示「端口 4173 已被其它程序占用」：关掉占用端口的程序，或设置 `$env:PORT=5000` 后重新启动。
- 显示「没有找到 Qwen3-VL-2B-Instruct 权重目录」：用 `OPENBRIDGE_MODEL_DIR` 指定，或把权重放到 `<项目>\model\Qwen3-VL-2B-Instruct`。
- 显示「没有找到带 torch + transformers 的 Python」：按第 3.2 节创建环境，或用 `OPENBRIDGE_PYTHON` 指定。
- 不要把 Token、Cookie、个人信息、生产日志或模型权重上传到公开成果链接。
